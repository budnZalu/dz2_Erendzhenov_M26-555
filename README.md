# Primitive DB

Автор: **Эрендженов (Erendzhenov)**. Группа: **M26-555**.

Учебная консольная база данных на Python 3.12 и выше. Реализованы подготовка
пакета, управление таблицами и полный набор CRUD-операций. Структура и данные
сохраняются в JSON, записи выводятся через PrettyTable. Декораторы
обрабатывают ошибки, подтверждают удаление и измеряют время; замыкание
кэширует выборки. Используется процедурный подход.

[Репозиторий проекта](https://github.com/budnZalu/dz2_Erendzhenov_M26-555).

## Установка и запуск

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/)
и `make` (GNU Make или системный Make), затем выполните:

```sh
git clone https://github.com/budnZalu/dz2_Erendzhenov_M26-555.git
cd dz2_Erendzhenov_M26-555
make install
make run
```

`make install` выполняет `uv sync --locked`, а `make run` —
`uv run --locked database`. Makefile сохраняет управление через uv из первой
части задания и предоставляет команды из финального чек-листа.

Также доступны `uv run python -m primitive_db.main` и прежняя команда
`uv run project`. После `source .venv/bin/activate` можно запускать `database`
без префикса `uv run`.

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу с указанными столбцами |
| `list_tables` | Показать все таблицы в алфавитном порядке |
| `drop_table <имя>` | Удалить таблицу и данные после подтверждения |
| `help` | Повторно показать справку |
| `exit` | Завершить работу |

Поддерживаются только типы `int`, `str`, `bool`. Нужен хотя бы один столбец.
`ID:int` добавляется автоматически и всегда стоит первым. Если пользователь
уже передал `ID:int`, повторный столбец не создаётся. Другой тип у `ID` и
повторяющиеся имена столбцов считаются ошибкой.

Имена таблиц и столбцов чувствительны к регистру. Они состоят из букв,
цифр и подчёркиваний и не могут начинаться с цифры; допускается кириллица.
Команды управления таблицами разбираются через `shlex.split`, поэтому
имена можно заключать в кавычки, например `create_table "users" "name:str"`.

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: create_table users name:str
Ошибка валидации: Таблица "users" уже существует.

>>>Введите команду: list_tables
- users

>>>Введите команду: create_table products price:float
Ошибка валидации: Некорректное значение: price:float. Попробуйте снова.

>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Таблица "users" успешно удалена.

>>>Введите команду: drop_table products
Ошибка валидации: Таблица "products" не существует.

>>>Введите команду: exit
Выход из программы.
```

Пустой ввод пропускается. Неизвестные команды, неверное число аргументов,
ошибки типов и незакрытые кавычки сопровождаются сообщением, после которого
можно продолжить работу. Ctrl+C и конец ввода (Ctrl+D в Unix) завершают
программу без трассировки ошибки. Во время подтверждения удаления они
отменяют текущую операцию.

## CRUD-операции

| Команда | Действие |
| --- | --- |
| `insert into <таблица> values (<значение1>, ...)` | Добавить запись без передачи ID |
| `select from <таблица>` | Вывести все записи |
| `select from <таблица> where <столбец> = <значение>` | Вывести записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить все совпадения |
| `delete from <таблица> where <столбец> = <значение>` | Удалить все совпадения после подтверждения |
| `info <таблица>` | Вывести структуру и количество записей |

Значения в `insert` идут в порядке столбцов схемы, **без ID**. Все поля
обязательны: пропуски, лишние значения и `null` отклоняются. Типы проверяются
строго: `28` — число, `"28"` — строка, `true` и `false` — логические значения.
Строки обязательно заключаются в одинарные или двойные кавычки; пустая
строка `""` допустима для `str`. В строках поддерживаются пробелы, запятые,
скобки и экранированные кавычки. Для управляющих символов используется
JSON-экранирование (`\n`, `\t`, `\u0410`); также разрешено `\'`.
Например: `"Он сказал: \"привет\""`.

Условие `where` — одно равенство. Для `update` и `delete` оно обязательно;
для `select` может отсутствовать. В `set` можно указать несколько полей
через запятую. Имена и типы проверяются даже при отсутствии совпадений.
Если записей не найдено, программа сообщает об этом без изменения файла.

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: insert into users values ("Sergei", 28, true)
Функция insert выполнилась за 0.000 секунд
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
Функция select выполнилась за 0.000 секунд
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Функция select выполнилась за 0.000 секунд
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Функция select выполнилась за 0.000 секунд
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

Пример обновления двух полей:

```text
update users set age=30, is_active=false where name="Sergei"
```

ID вычисляется как `max(ID существующих записей) + 1`, начиная с 1.
Изменять ID через `update` нельзя. Удаление записи в середине списка не
приводит к дублированию ключей; после удаления максимального ID или всех
записей освободившийся ID может использоваться снова.

## Декораторы и замыкания

Модуль `src/primitive_db/decorators.py` входит в устанавливаемый пакет.
Все декораторы сохраняют имя, документацию и ссылку `__wrapped__` исходной
функции через общий помощник `_preserve_metadata`. Это позволяет соблюдать
ограничение на стандартные модули из финального чек-листа.

- `handle_db_errors` оборачивает все шесть операций `core.py` и обработчики
  команд в `engine.py`. Он перехватывает `KeyError`, `ValueError`,
  `FileNotFoundError`, остальные `OSError` и непредвиденные `Exception`,
  печатает понятное сообщение и возвращает `None`. Интерфейс проверяет
  результат перед сохранением: ошибка не записывается в JSON и не
  сопровождается сообщением об успехе. `KeyboardInterrupt` и `SystemExit`
  этим декоратором не подавляются.
- `confirm_action(action_name)` — фабрика декораторов для `drop_table` и
  `delete`. **Только точный ответ `y` подтверждает действие**. Любой другой
  ввод, Ctrl+C или конец ввода отменяет его без перезаписи файлов. Для
  неверной команды или отсутствующих записей CLI не запрашивает подтверждение.
- `log_time` оборачивает `insert` и `select`, используя `time.monotonic()`.
  Он выводит `Функция select выполнилась за X.XXX секунд`, в том числе при
  ошибке и попадании в кэш. Измеряется вызов функции ядра; отдельное чтение
  и сохранение в `engine.py` в это время не входят. Значения в примерах
  приблизительные. `update` и `delete` также вызывают `select` для поиска
  совпадений, поэтому перед ними появляется время выборки.

```text
>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.
>>>Введите команду: list_tables
- users
```

`create_cacher()` возвращает `cache_result(key, value_func)` со словарём
в замыкании. Повторный ключ возвращает сохранённый результат без вызова
`value_func`; кэшируются также пустые результаты и `None`. Исключения
вычисления не кэшируются, каждый вызов фабрики создаёт независимый кэш.

В `select` ключ содержит снимок всех записей и условие с точными типами
значений: `True` и `1` различаются. После вставки, обновления, удаления,
повторного создания таблицы или внешнего изменения JSON изменённые данные
получают другой ключ. Результат возвращается в виде копий записей, поэтому
его изменение не повреждает кэш или исходную таблицу. Кэш хранится в памяти
до завершения процесса. Чтение JSON, проверка данных и построение ключа
выполняются при каждом запросе; повторно не выполняется фильтрация.

Проверки схемы и типов вынесены в `validation.py`: они передают исключение
до декоратора текущей операции, останавливая её до изменения данных.
В `core.py` нет повторяющихся блоков `try/except`. В интерфейсе сохранены
блоки для разбора ввода и загрузки метаданных; откат неудачного удаления
файла находится в `utils.py`. Эти блоки выполняют отдельную работу и не
дублируют декоратор.

## Хранение метаданных и записей

Файл `db_meta.json` создаётся **в текущей рабочей папке** после первой
успешной операции изменения таблиц. Пример содержимого:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

При повторном запуске из той же папки таблицы сохраняются. Каждый проход
цикла заново загружает файл. Отсутствующий файл означает пустую базу.
Некорректный JSON или неподходящая структура вызывают сообщение об ошибке;
исходный файл сохраняется, а `help` и `exit` остаются доступны.

Файл меняется только после успешного создания или удаления таблицы.
Запись сначала выполняется во временный файл, затем заменяет исходный JSON.
Сообщение об успехе выводится только после сохранения на диск.

Записи каждой таблицы хранятся отдельно: например, `data/users.json`.
Каталог и файл создаются при первой успешной вставке. Таблица без файла
данных считается пустой, в том числе таблица из предыдущей версии проекта.

```json
[
  {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```

Изменения записей сохраняются после успешных `insert`, `update` и `delete`.
Все данные проверяются по схеме перед операцией: пропущенные и лишние поля,
неверные типы и повторяющиеся ID приводят к ошибке без перезаписи файла.
`drop_table` удаляет и схему, и файл данных; повторное создание таблицы
начинает её с пустого состояния. Файл данных без схемы не перезаписывается
при создании одноимённой таблицы — сначала нужно проверить или перенести его.

Для работы с той же базой запускайте приложение из той же папки.
Одновременное изменение базы несколькими процессами не поддерживается.

## Проверки

```sh
make lint
make format-check
make test
# Все три проверки одной командой:
make check
```

58 тестов проверяют управление таблицами, CRUD, генерацию ID, строгие типы,
кавычки и разделители в строках, обязательные поля, несколько совпадений,
сохранение между запусками, повреждённые файлы, ошибки записи, удаление
данных вместе с таблицей, Ctrl+C и завершение ввода. Дополнительно проверяются
подтверждение и отмена операций, сохранность файлов при отмене, точный формат
таймера, сохранение метаданных функций, повторное использование кэша,
независимость копий и актуальность выборок после изменения данных. Проверяются
также Unicode и экранирование строк, очистка временного файла при ошибке
сериализации и сохранность чужого временного файла при совпадении имени.

В `.github/workflows/check.yml` настроены проверки на каждый push и pull
request: `make install`, `make check`, `make build` на Python 3.12.
[Результаты GitHub Actions](https://github.com/budnZalu/dz2_Erendzhenov_M26-555/actions/workflows/check.yml).
Это проверки репозитория; результаты отдельных закрытых тестов учебной
платформы нужно смотреть на самой платформе после отправки проекта.

Ruff установлен только для разработки. Включены правила `E`, `F`, `I`,
максимальная длина строки 88 и целевая версия Python 3.12. Для uv зависимость
находится в `[dependency-groups].dev`, для совместимости с Poetry также
указана в `[tool.poetry.group.dev.dependencies]`; в runtime её нет.
`poetry check --strict` проверяет совместимость конфигурации.

Код приложения использует только стандартные `json`, `shlex`, `time`, `os`
и внешние `prettytable`, `prompt`. Классов в `src/primitive_db` нет;
все операции реализованы функциями. Автотесты находятся отдельно в `tests/`.
Общие имена файлов, команд и типов, описание поля ID и настройки JSON
вынесены в `constants.py`. Проверки файлов и откат удаления выполняются
в `utils.py`; интерфейс вызывает готовые операции хранения.
Разработка ведётся в тематических ветках `codex/`, которые после проверок
объединяются с `main`; история содержит отдельные коммиты этапов проекта.

## Сборка и установка CLI из wheel

```sh
make build
uvx twine check dist/*
uv tool install --upgrade dist/primitive_db-0.6.1-py3-none-any.whl
database
```

`twine check` проверяет метаданные локально; пакет на PyPI не публикуется.
Wheel устанавливается в отдельное окружение uv, команда `database`
работает вне папки исходников. Если каталог инструментов отсутствует
в `PATH`, выполните `uv tool update-shell` и перезапустите терминал.

`constants.py` хранит общие константы.
`core.py` управляет таблицами и выполняет CRUD. `validation.py` проверяет
схемы и типы; `decorators.py` содержит три декоратора и фабрику кэша.
`parser.py` разбирает CRUD-команды, сохраняя кавычки и типы значений.
`engine.run()` выполняет основной цикл и выводит результат через PrettyTable.
`utils.py` читает и атомарно сохраняет JSON. `main.py` — точка входа;
импорт модулей не запускает программу. Окружение, сборки, кэши,
пользовательские `db_meta.json` и `data/` исключены из Git.
