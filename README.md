# Primitive DB

Автор: **Эрендженов (Erendzhenov)**. Группа: **M26-555**.

Учебная консольная база данных на Python 3.12 и выше. Реализованы подготовка
пакета, управление таблицами и полный набор CRUD-операций. Структура и данные
сохраняются в JSON, записи выводятся через PrettyTable. Используется
процедурный подход.

[Репозиторий проекта](https://github.com/budnZalu/dz2_Erendzhenov_M26-555).

## Установка и запуск

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/),
затем выполните:

```sh
git clone https://github.com/budnZalu/dz2_Erendzhenov_M26-555.git
cd dz2_Erendzhenov_M26-555
uv sync
uv run database
```

Также доступны `uv run python -m primitive_db.main` и прежняя команда
`uv run project`. После `source .venv/bin/activate` можно запускать `database`
без префикса `uv run`.

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя> <столбец:тип> ...` | Создать таблицу с указанными столбцами |
| `list_tables` | Показать все таблицы в алфавитном порядке |
| `drop_table <имя>` | Удалить таблицу |
| `help` | Повторно показать справку |
| `exit` | Завершить работу |

Поддерживаются только типы `int`, `str`, `bool`. Нужен хотя бы один столбец.
`ID:int` добавляется автоматически и всегда стоит первым. Если пользователь
уже передал `ID:int`, повторный столбец не создаётся. Другой тип у `ID` и
повторяющиеся имена столбцов считаются ошибкой.

Имена таблиц и столбцов чувствительны к регистру. Они состоят из букв,
цифр и подчёркиваний и не могут начинаться с цифры; допускается кириллица.
Команды управления таблицами разбираются через `shlex.split`, поэтому
имена можно заключать в кавычки, например `create_table "users" "name:str"`.

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.

>>>Введите команду: list_tables
- users

>>>Введите команду: create_table products price:float
Некорректное значение: price:float. Попробуйте снова.

>>>Введите команду: drop_table users
Таблица "users" успешно удалена.

>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.

>>>Введите команду: exit
Выход из программы.
```

Пустой ввод пропускается. Неизвестные команды, неверное число аргументов,
ошибки типов и незакрытые кавычки сопровождаются сообщением, после которого
можно продолжить работу. Ctrl+C и конец ввода (Ctrl+D в Unix) завершают
программу без трассировки ошибки.

## CRUD-операции

| Команда | Действие |
| --- | --- |
| `insert into <таблица> values (<значение1>, ...)` | Добавить запись без передачи ID |
| `select from <таблица>` | Вывести все записи |
| `select from <таблица> where <столбец> = <значение>` | Вывести записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить все совпадения |
| `delete from <таблица> where <столбец> = <значение>` | Удалить все совпадения |
| `info <таблица>` | Вывести структуру и количество записей |

Значения в `insert` идут в порядке столбцов схемы, **без ID**. Все поля
обязательны: пропуски, лишние значения и `null` отклоняются. Типы проверяются
строго: `28` — число, `"28"` — строка, `true` и `false` — логические значения.
Строки обязательно заключаются в одинарные или двойные кавычки; пустая
строка `""` допустима для `str`. В строках поддерживаются пробелы, запятые,
скобки и экранированные кавычки. Например: `"Он сказал: \"привет\""`.

Условие `where` — одно равенство. Для `update` и `delete` оно обязательно;
для `select` может отсутствовать. В `set` можно указать несколько полей
через запятую. Имена и типы проверяются даже при отсутствии совпадений.
Если записей не найдено, программа сообщает об этом без изменения файла.

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

Пример обновления двух полей:

```text
update users set age=30, is_active=false where name="Sergei"
```

ID вычисляется как `max(ID существующих записей) + 1`, начиная с 1.
Изменять ID через `update` нельзя. Удаление записи в середине списка не
приводит к дублированию ключей; после удаления максимального ID или всех
записей освободившийся ID может использоваться снова.

## Хранение метаданных и записей

Файл `db_meta.json` создаётся **в текущей рабочей папке** после первой
успешной операции изменения таблиц. Пример содержимого:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

При повторном запуске из той же папки таблицы сохраняются. Каждый проход
цикла заново загружает файл. Отсутствующий файл означает пустую базу.
Некорректный JSON или неподходящая структура вызывают сообщение об ошибке;
исходный файл сохраняется, а `help` и `exit` остаются доступны.

Файл меняется только после успешного создания или удаления таблицы.
Запись сначала выполняется во временный файл, затем заменяет исходный JSON.
Сообщение об успехе выводится только после сохранения на диск.

Записи каждой таблицы хранятся отдельно: например, `data/users.json`.
Каталог и файл создаются при первой успешной вставке. Таблица без файла
данных считается пустой, в том числе таблица из предыдущей версии проекта.

```json
[
  {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```

Изменения записей сохраняются после успешных `insert`, `update` и `delete`.
Все данные проверяются по схеме перед операцией: пропущенные и лишние поля,
неверные типы и повторяющиеся ID приводят к ошибке без перезаписи файла.
`drop_table` удаляет и схему, и файл данных; повторное создание таблицы
начинает её с пустого состояния. Файл данных без схемы не перезаписывается
при создании одноимённой таблицы — сначала нужно проверить или перенести его.

Для работы с той же базой запускайте приложение из той же папки.
Одновременное изменение базы несколькими процессами не поддерживается.

## Сборка и установка CLI из wheel

```sh
uv build
uvx twine check dist/*
uv tool install --upgrade dist/primitive_db-0.4.0-py3-none-any.whl
database
```

`twine check` проверяет метаданные локально; пакет на PyPI не публикуется.
Wheel устанавливается в отдельное окружение uv, команда `database`
работает вне папки исходников. Если каталог инструментов отсутствует
в `PATH`, выполните `uv tool update-shell` и перезапустите терминал.

## Структура проекта

```text
dz2_Erendzhenov_M26-555/
├── docs/
│   ├── demo.cast
│   └── crud-demo.cast
├── src/
│   └── primitive_db/
│       ├── __init__.py
│       ├── core.py
│       ├── engine.py
│       ├── main.py
│       ├── parser.py
│       └── utils.py
├── tests/
│   ├── test_database.py
│   └── test_crud.py
├── .gitignore
├── .python-version
├── pyproject.toml
├── uv.lock
└── README.md
```

`core.py` управляет таблицами, проверяет типы и выполняет CRUD.
`parser.py` разбирает CRUD-команды, сохраняя кавычки и типы значений.
`engine.run()` выполняет основной цикл и выводит результат через PrettyTable.
`utils.py` читает и атомарно сохраняет JSON. `main.py` — точка входа;
импорт модулей не запускает программу. Окружение, сборки, кэши,
пользовательские `db_meta.json` и `data/` исключены из Git.
